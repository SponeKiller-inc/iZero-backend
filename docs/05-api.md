# 05 – API

Base prefix: `/api`. The router is composed in [app/infrastructure/api/router.py](../app/infrastructure/api/router.py).

Interactive documentation generated by FastAPI: `/docs` (Swagger UI), `/redoc`, schema at `/openapi.json`.

## Response format

All responses use the `ResponseContainer` envelope ([schemas/base.py](../app/infrastructure/api/schemas/base.py)):

```json
{
  "message_id": 1000001,
  "message": "optional text",
  "data": null
}
```

| Field | Description |
|-------|-------------|
| `message_id` | Numeric message code, see below |
| `message` | Optional accompanying text (not intended for end users) |
| `data` | Endpoint payload, typed via a generic |

## Schema naming

Pydantic schema classes in `app/infrastructure/api/schemas/**` are suffixed `SchemaIn` / `SchemaOut`
(e.g. `ModuleSchemaIn`, `ModuleSchemaOut`), not just `In` / `Out`. This distinguishes them from the
application-layer DTOs in `app/application/dto/**`, which keep the plain `In` / `Out` suffix
(e.g. `CreateModuleIn`, `CreateModuleOut`).

When mapping a use-case DTO to its `SchemaOut`, prefer `SomeSchemaOut.model_validate(result)` over listing
every field manually. This requires the schema to declare `model_config = ConfigDict(from_attributes=True)`,
and only works when field names match between the DTO and the schema — use `Field(validation_alias="...")`
for the fields that don't (see `TokenSchemaOut` in [schemas/token.py](../app/infrastructure/api/schemas/token.py)).

## Message IDs

Defined in [schemas/message_id.py](../app/infrastructure/api/schemas/message_id.py). Code format: `EE SS NNN` — 2 digits for the main entity, 2 digits for the sub-entity, 3 digits for the sequence number.

| Code | Constant | Meaning |
|------|----------|---------|
| 1000001 | `USER_NOT_FOUND` | User not found |
| 1000002 | `USER_ALREADY_EXISTS` | User with this e-mail / provider account already exists |
| 1000003 | `USER_CANNOT_BE_DELETED` | User is protected (bootstrap admin) |
| 1000004 | `USER_INVALID_CURRENT_PASSWORD` | Current password is wrong |
| 1000005 | `USER_PASSWORD_TOO_SHORT` | New password is shorter than 8 characters |
| 1000006 | `USER_PASSWORD_TOO_LONG` | New password is longer than 128 characters |
| 1000007 | `USER_PASSWORD_SAME_AS_CURRENT` | New password equals the current one |
| 1000008 | `USER_PASSWORD_CHANGE_NOT_SUPPORTED` | Account has no password (registered via Google) |
| 1000009 | `USER_PASSWORD_CONFIRMATION_MISMATCH` | Password confirmation differs from the new password |
| 1000010 | `USER_INVALID_ID` | `user_id` in the path is not a number (400) |
| 2000001 | `AUTH_NOT_AUTHENTICATED` | User is not authenticated |
| 2000002 | `AUTH_NOT_AUTHORIZED` | User lacks permission |
| 2000003 | `AUTH_NOT_ACCESS` | Access denied |
| 2000004 | `AUTH_IDENTITY_PROVIDER_FAILED` | External identity provider rejected the token |
| 4000001 | `MODULE_GROUP_NOT_FOUND` | Module group does not exist |
| 5000001 | `ADDRESS_NOT_FOUND` | Address does not exist |
| 5000002 | `ADDRESS_TYPE_NOT_FOUND` | Address type does not exist |
| 6000001 | `BANK_NOT_FOUND` | Bank is not in the bank catalogue |
| 6010001 | `BANK_ACCOUNT_NOT_FOUND` | User has no bank account |
| 6010002 | `BANK_ACCOUNT_ALREADY_EXISTS` | User already has a bank account |
| 6010003 | `BANK_ACCOUNT_VALIDATION_FAILED` | Bank account violates the bank account rules (`BankAccountValidationError` — invalid format of account prefix, account number or IBAN, empty owner name, IBAN is not a Czech one) |
| 7000001 | `PERSON_NOT_FOUND` | User has no person, or the assigned person's details do not exist |
| 7000002 | `PERSON_ALREADY_EXISTS` | User already has a person |
| 7000003 | `PERSON_TYPE_CHANGE_NOT_ALLOWED` | Changed details belong to another person type than the user's person has |
| 7000004 | `PERSON_VALIDATION_FAILED` | Person details violate the person rules (`PersonValidationError` — invalid IČO or VAT ID, empty name, age under 18, unknown title or legal form, VAT payer without VAT ID) |
| 8000001 | `PHONE_VALIDATION_FAILED` | Phone violates the phone rules (`PhoneValidationError` — incomplete phone, unknown calling code, number that is not a Czech 9-digit number) |
| 8010001 | `EMAIL_VALIDATION_FAILED` | E-mail address has invalid format (`EmailValidationError`) |
| 9000001 | `SYSTEM_INTERNAL_FAIL` | Unexpected server error |

When adding a new code, add a row to this table.

Endpoints do not catch application errors. Each error is mapped to its message ID and status code in
[errors](../app/infrastructure/api/errors), organized like the endpoints and joined in its `__init__.py`, and answered by a global handler in
[main.py](../app/infrastructure/api/main.py). The error passes through `get_db`, which rolls the transaction back, so a
rejected request stores nothing. An application error missing from the mapping ends as `SYSTEM_INTERNAL_FAIL` (500).
The token endpoints are the exception: they catch their errors and raise `HTTPException` with their own response.

## HTTP status codes

| Code | Usage |
|------|-------|
| 200 / 201 | Success |
| 204 | Success with no body |
| 400 | Invalid input |
| 401 | Missing or invalid authentication |
| 403 | Insufficient permissions |
| 404 | Resource does not exist |
| 409 | Conflict with the current state (e.g. duplicate user, protected user) |
| 422 | Pydantic validation error |
| 500 | Unexpected error (reported to Sentry) |

#### `PUT /api/users/{user_id}/password`

- **Purpose:** Change the password of the user `user_id` (`ChangePassword` use-case). The current session stays valid
  and records a `password_changed` event.
- **Authentication:** authenticated, `@authorize(EntityType.USERS, UseCase.USERS_CHANGE_PASSWORD)` (granted to the
  regular role by `SeedDefaultRolePermissions`). Only accounts created locally or by seed.
- **Input:** `ChangePasswordSchemaIn` ([schemas/user/user.py](../app/infrastructure/api/schemas/user/user.py)) —
  `current_password`, `new_password`, `password_confirmation`. Length rules are enforced in the domain
  (`Password` value object), not in the schema.
- **Response:** empty body, `204 No Content`.
- **Errors:** `AUTH_NOT_AUTHENTICATED` (401), `AUTH_NOT_ACCESS` (403), `AUTH_NOT_AUTHORIZED` (403) if `user_id` is not
  the authenticated caller, `USER_NOT_FOUND` (404), `USER_INVALID_CURRENT_PASSWORD`,
  `USER_PASSWORD_TOO_SHORT`, `USER_PASSWORD_TOO_LONG`, `USER_PASSWORD_CONFIRMATION_MISMATCH`,
  `USER_PASSWORD_SAME_AS_CURRENT` (400), `USER_PASSWORD_CHANGE_NOT_SUPPORTED` (409). A refused request changes nothing.

#### `DELETE /api/users/{user_id}`

- **Purpose:** Soft delete the caller's own account (`DeleteUser` use-case) — sets `users.is_active = false`, no rows are removed.
  An inactive user cannot log in (local or Google) and any access token issued before the delete is rejected
  by `Authenticate` with `401`.
- **Authentication:** authenticated, `@authorize(EntityType.USERS, UseCase.USERS_DELETE)` — seeded for the regular role.
- **Input:** path parameter `user_id`.
- **Response:** `204 No Content`.
- **Errors:** `AUTH_NOT_AUTHORIZED` (403) if `user_id` is not the authenticated caller, `USER_NOT_FOUND` (404) if the user does not exist or is already inactive (a repeated self-delete with the same token
  is rejected earlier by `Authenticate` with `401` `AUTH_NOT_AUTHENTICATED`), `USER_CANNOT_BE_DELETED` (409)
  for the bootstrap admin.

#### `GET | POST | PUT /api/users/{user_id}/person`

- **Purpose:** View, add and change the person details of the user `user_id` (`RetrieveUserPerson`, `AddUserPerson`,
  `ChangeUserPerson` use-cases). A user has at most one person, assigned through `user_persons`; the person type cannot
  be changed once added.
- **Authentication:** authenticated, `@authorize(EntityType.PERSONS, UseCase.PERSONS_RETRIEVE_USER_PERSON | PERSONS_ADD_USER_PERSON | PERSONS_CHANGE_USER_PERSON)`
  (granted to the regular role by `SeedDefaultRolePermissions`). `user_id` must be the authenticated caller.
- **Input (POST, PUT):** `UserPersonSchemaIn` ([schemas/user/user_person.py](../app/infrastructure/api/schemas/user/user_person.py)) —
  the field `person` carries the details of the requested type (`NaturalPersonSchemaIn`, `EntrepreneurSchemaIn` or
  `CompanySchemaIn`), told apart by their fields. All fields are required, optional ones are sent as `null`, and unknown
  fields are ignored. A company carries its `representative` as natural person fields. `addresses` is a list of
  `address_id` and `address_type_id`; a changed address ends the previous one of its type, which
  stays in history, and a type not listed keeps its current address (PUT).
- **Response:** `UserPersonSchemaOut` ([schemas/user/user_person.py](../app/infrastructure/api/schemas/user/user_person.py)), based on `PersonSchemaOut` — `id`, `person_type` and the details of the type in `natural_person`, `entrepreneur`
  or `company` (the others are `null`); each of them carries its current `addresses` (`id`, `address_type`, `address`). `200` (GET, PUT), `201` (POST). GET returns `data: null` when the user has no person.
- **Errors:** `AUTH_NOT_AUTHENTICATED` (401), `AUTH_NOT_ACCESS` (403), `AUTH_NOT_AUTHORIZED` (403) if `user_id` is not the
  authenticated caller, `USER_INVALID_ID` (400), `PERSON_NOT_FOUND` (404), `PERSON_ALREADY_EXISTS` (409, POST),
  `PERSON_TYPE_CHANGE_NOT_ALLOWED` (409, PUT), `ADDRESS_NOT_FOUND`, `ADDRESS_TYPE_NOT_FOUND` (404, POST, PUT), `PERSON_VALIDATION_FAILED`, `PHONE_VALIDATION_FAILED`,
  `EMAIL_VALIDATION_FAILED` (400).

### Modules — `/api/modules`

Implemented in [endpoints/module](../app/infrastructure/api/endpoints/module), use-cases in
[use_cases/modules](../app/application/use_cases/modules).

#### `POST /api/modules`

- **Purpose:** Create a new module.
- **Authentication:** authenticated, `@authorize(EntityType.MODULES, UseCase.MODULES_CREATE)`.
- **Input:** `ModuleSchemaIn` ([schemas/module/module.py](../app/infrastructure/api/schemas/module/module.py)) — `name`, `module_group_id`, `valid_from`.
- **Response:** `ResponseContainer[ModuleSchemaOut]`, `201 Created`.
- **Errors:** `MODULE_GROUP_NOT_FOUND` (404) if `module_group_id` does not exist.

#### `POST /api/modules/groups`

- **Purpose:** Create a new module group.
- **Authentication:** authenticated, `@authorize(EntityType.MODULES, UseCase.MODULES_CREATE_GROUP)`.
- **Input:** `ModuleGroupSchemaIn` ([schemas/module/module_group.py](../app/infrastructure/api/schemas/module/module_group.py)) — `name`, `valid_from`.
- **Response:** `ResponseContainer[ModuleGroupSchemaOut]`, `201 Created`.
- **Errors:** none besides validation/auth.

### Lookups — `/api/lookups`

Implemented in [endpoints/lookup](../app/infrastructure/api/endpoints/lookup), use-cases in
[use_cases/lookup](../app/application/use_cases/lookup).

#### `GET /api/lookups/legal-forms`

- **Purpose:** Retrieve the legal form catalogue, e.g. to get the `legal_form_id` of a company.
- **Authentication:** authenticated, `@authorize(EntityType.PERSONS, UseCase.PERSONS_RETRIEVE_LEGAL_FORMS)`.
- **Input:** none.
- **Response:** `ResponseContainer[list[LegalFormSchemaOut]]` ([schemas/lookup/legal_form.py](../app/infrastructure/api/schemas/lookup/legal_form.py)) — `id`, `code`, `name`; `200 OK`.
- **Errors:** none besides auth.

#### `GET /api/lookups/titles`

- **Purpose:** Retrieve the title catalogue, e.g. to get the `title_ids` of a natural person.
- **Authentication:** authenticated, `@authorize(EntityType.PERSONS, UseCase.PERSONS_RETRIEVE_TITLES)`.
- **Input:** none.
- **Response:** `ResponseContainer[list[TitleSchemaOut]]` ([schemas/lookup/title.py](../app/infrastructure/api/schemas/lookup/title.py)) — `id`, `title_type`, `name`; prefix titles first, each type ordered by priority; `200 OK`.
- **Errors:** none besides auth.

#### `GET /api/lookups/phone-prefixes`

- **Purpose:** Retrieve the phone prefix catalogue, e.g. to get the `phone_prefix_id` of a person.
- **Authentication:** authenticated, `@authorize(EntityType.CONTACTS, UseCase.CONTACTS_RETRIEVE_PHONE_PREFIXES)`.
- **Input:** none.
- **Response:** `ResponseContainer[list[PhonePrefixSchemaOut]]` ([schemas/lookup/phone_prefix.py](../app/infrastructure/api/schemas/lookup/phone_prefix.py)) — `id`, `prefix`, `country_id`; ordered by prefix; `200 OK`.
- **Errors:** none besides auth.

### Tokens — `/api/auth/token`

Implemented in [endpoints/auth/token.py](../app/infrastructure/api/endpoints/auth/token.py), use-cases in
[use_cases/auth](../app/application/use_cases/auth). Unlike the endpoints above, these responses are **not** wrapped
in `ResponseContainer` — they return `TokenSchemaOut` directly and use plain `HTTPException(detail=...)` for errors.

A session (see [middleware/sid.py](../app/infrastructure/api/middleware/sid.py)) must already exist before these are
called — `SIDMiddleware` initializes one on every request, so login use-cases never validate session existence
themselves; they read `request.state.session_id`.

#### `POST /api/auth/token/local`

- **Purpose:** Log in with e-mail + password (`LoginLocal` use-case).
- **Authentication:** public.
- **Input:** `OAuth2PasswordRequestForm` (form fields `username` = e-mail, `password`).
- **Response:** `TokenSchemaOut` (`access_token`, `token_type`), `200 OK`. Also sets httpOnly/secure `refresh_token` and
  secure `csrf_token` cookies.
- **Errors:** `401` "Invalid credentials" (`InvalidCredentialsError` — unknown or inactive user, no local password, or bad password).

#### `POST /api/auth/token/google`

- **Purpose:** Log in with a Google `id_token` (`LoginGoogle` use-case). The user must already be registered via
  `POST /api/users/google`; this endpoint does not create new users.
- **Authentication:** public.
- **Input:** `GoogleTokenSchemaIn` ([schemas/token.py](../app/infrastructure/api/schemas/token.py)) — `jwt_token`.
- **Response:** `TokenSchemaOut`, `200 OK`. Same cookies as `/local`.
- **Errors:** `401` "Invalid credentials" (`UserNotFoundError` — no active user for that Google account), `400` "Google
  authentication failed" (`IdentityProviderError` — invalid/expired Google token).

Note: an earlier `GET /token/me` endpoint referenced non-existent modules and was dead code; it has been removed.
